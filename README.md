## 🔷 기능 요구사항 정리

| **구분**         | **기능명**      | **세부 설명**                                                                                                         |
|----------------|--------------|-------------------------------------------------------------------------------------------------------------------|
| **입력**         | 로또 구입 금액 입력  | 사용자에게 `"구입금액을 입력해 주세요."` 메시지와 함께 로또 구입 금액을 입력받는다.                                                                 |
|                | 당첨 번호 입력     | 사용자에게 `"당첨 번호를 입력해 주세요."` 메시지와 함께 당첨 번호를 입력받는다.                                                                   |
|                | 보너스 번호 입력    | 사용자에게 `"보너스 번호를 입력해 주세요."` 메시지와 함께 보너스 번호를 입력받는다.                                                                 |
|                | 잘못된 입력 재입력   | 잘못된 입력 발생 시 `[ERROR]` 메시지를 출력하고 해당 입력 단계부터 다시 입력받는다.                                                              |
| **입력 전처리**     | 구입 금액 전처리    | 입력받은 문자열의 앞뒤 공백을 제거하고 숫자로 변환한다. 변환 실패 시 예외 처리(`"구입 금액은 숫자여야 합니다."`, `"구입 금액은 최대 9223372036854775807 이하여야 합니다."`). |
|                | 당첨 번호 파싱     | 입력받은 당첨 번호를 쉼표(`,`)로 분리한다.                                                                                        |
|                | 당첨 번호 전처리    | 각 당첨 번호의 앞뒤 공백을 제거하고 정수로 변환한다. 변환 불가 시 예외 처리한다.                                                                   |
|                | 보너스 번호 전처리   | 입력받은 보너스 번호의 앞뒤 공백을 제거하고 정수로 변환한다. 변환 불가 시 예외 처리한다.                                                               |
| **입력 검증**      | 구입 금액 양수 검증  | 구입 금액이 0보다 큰지 검증한다. 그렇지 않으면 예외 처리(`"구입 금액은 양수여야 합니다."`).                                                          |
|                | 구입 금액 단위 검증  | 구입 금액이 1,000원 단위로 나누어떨어지는지 검증한다. 그렇지 않으면 예외 처리(`"구입 금액은 1,000원 단위여야 합니다."`).                                      |
|                | 당첨 번호 개수 검증  | 파싱된 당첨 번호가 6개인지 검증하고, 그렇지 않으면 예외 처리한다.                                                                            |
|                | 당첨 번호 범위 검증  | 각 당첨 번호가 1~45 범위 내에 있는지 검증하고, 벗어나면 예외 처리한다.                                                                       |
|                | 당첨 번호 중복 검증  | 당첨 번호 6개가 중복되지 않는지 검증하고, 중복 시 예외 처리한다.                                                                            |
|                | 보너스 번호 범위 검증 | 보너스 번호가 1~45 범위의 숫자인지 검증하고, 벗어나면 예외 처리한다.                                                                         |
|                | 보너스 번호 중복 검증 | 보너스 번호가 당첨 번호 6개와 중복되지 않는지 검증하고, 중복 시 예외 처리한다.                                                                    |
| **로또 생성 및 발행** | 로또 수량 계산     | 구입 금액을 1,000원으로 나누어 구매할 로또 수량을 계산한다.                                                                              |
|                | 로또 발행        | 계산된 수량만큼 로또를 발행한다. 각 로또는 1~45 범위에서 중복 없는 6개의 숫자로 구성된다.                                                            |
|                | 난수 생성 방식     | `Randoms.pickUniqueNumbersInRange(1, 45, 6)`을 사용해 중복 없는 번호를 생성한다.                                                 |
|                | 로또 번호 정렬     | 발행된 각 로또 번호를 오름차순으로 정렬한다.                                                                                         |
| **당첨 결과 계산**   | 일치 번호 개수 계산  | 각 로또와 당첨 번호를 비교하여 일치하는 번호 개수를 계산한다.                                                                               |
|                | 보너스 번호 일치 확인 | 일치 번호가 5개인 경우 보너스 번호 일치 여부를 확인한다.                                                                                 |
|                | 당첨 순위 판정     | 일치 개수 및 보너스 번호 일치 여부에 따라 순위를 결정한다. (6개=1등, 5개+보너스=2등, 5개=3등, 4개=4등, 3개=5등)                                        |
|                | 당첨 통계 집계     | 모든 로또의 당첨 결과를 순위별로 집계한다.                                                                                          |
| **수익률 계산**     | 총 상금 계산      | 각 순위별 당첨 개수 × 상금을 모두 합산하여 총 상금을 계산한다.                                                                             |
|                | 수익률 계산       | `(총 상금 / 구입 금액) × 100`으로 계산한다.                                                                                    |
|                | 수익률 반올림      | 소수점 둘째 자리에서 반올림하여 소수점 첫째 자리까지 표시한다.                                                                               |
| **출력**         | 구매 결과 출력     | `"{수량}개를 구매했습니다."` 형식으로 구매 수량을 출력한다.                                                                              |
|                | 로또 번호 출력     | 발행된 모든 로또 번호를 한 줄에 하나씩 `[번호1, 번호2, ..., 번호6]` 형식으로 출력한다. (오름차순 정렬)                                                |
|                | 당첨 통계 헤더 출력  | `"당첨 통계"`와 구분선 `"---"`을 출력한다.                                                                                     |
|                | 당첨 내역 출력     | 5등 → 1등 순서대로 `"{일치 개수}개 일치 ({상금}원) - {개수}개"` 형식으로 출력한다. 2등은 `"5개 일치, 보너스 볼 일치 ({상금}원) - {개수}개"`.                  |
|                | 수익률 출력       | `"총 수익률은 {수익률}%입니다."` 형식으로 출력한다. 소수점 첫째 자리까지 표시한다.                                                                |

> 위 표는 기능 구현 목록을 담습니다. 프리코스 진행 방식에서 제시된 "기능 요구사항에 기재되지 않은 내용은 스스로 판단하여 구현한다"에 해당하는 내용은 아래 이렇게 판단했습니다에 기재했습니다.

## 🤔 이렇게 판단했습니다

- **입력값의 앞뒤 공백은 모두 제거하여 처리합니다**
    - 구입 금액, 당첨 번호, 보너스 번호 입력 시 문자열의 앞뒤 공백을 모두 제거합니다.
    - 당첨 번호의 경우 쉼표(`,`)로 분리한 뒤 각 번호의 앞뒤 공백 또한 제거합니다.
    - `"1,2,3,4,5,6"`과 `"1, 2, 3, 4, 5, 6"`을 동일하게 처리하기 위함이며, 사용자 입력 실수에 관대한 UX를 제공합니다.

- **입력 검증 실패 시 [ERROR] 메시지를 출력하고 재입력합니다**
    - 모든 예외는 `[ERROR]` 접두어를 붙여 출력합니다.
    - 잘못된 입력이 발생한 단계(구입 금액 / 당첨 번호 / 보너스 번호)부터 다시 입력을 받습니다.
    - 프로그램이 비정상 종료되지 않도록 `InputService`에서 재입력 루프를 관리합니다.

- **로또 번호는 중복되지 않으며, 범위는 1~45입니다**
    - 하나의 로또는 1~45 범위의 중복 없는 6개의 숫자로 구성됩니다.
    - 중복이나 범위 위반 시 예외를 발생시킵니다.
    - 각 로또의 번호는 생성 후 오름차순으로 정렬합니다.

- **보너스 번호는 당첨 번호와 중복될 수 없습니다**
    - 실제 로또 규칙에 따라, 보너스 번호는 당첨 번호 6개를 제외한 숫자 중 하나여야 합니다.
    - 따라서 보너스 번호가 당첨 번호 중 하나와 동일하면 잘못된 입력으로 간주하고 예외를 발생시킵니다.

- **로또 발행은 MissionUtils.Randoms를 사용합니다**
    - `camp.nextstep.edu.missionutils.Randoms.pickUniqueNumbersInRange(1, 45, 6)`을 통해 중복 없는 난수를 생성합니다.
    - 발행된 로또의 순서는 출력 시 오름차순으로 정렬되어 표시됩니다.

- **당첨 금액 기준은 고정 상수로 관리합니다**
    - 1등: 2,000,000,000원
    - 2등: 30,000,000원
    - 3등: 1,500,000원
    - 4등: 50,000원
    - 5등: 5,000원
    - 2개 이하 일치는 당첨 내역에서 제외합니다. (`Rank.NONE`)
    - 상금과 일치 개수 조건은 `Rank` Enum으로 관리하여 변경에 유연하도록 설계했습니다.

- **출력 순서와 형식은 요구사항과 일치하도록 고정했습니다**
    - 당첨 통계는 5등 -> 1등 순서로 출력합니다.
    - `"5개 일치, 보너스 볼 일치"` 형식은 2등에만 적용됩니다.
    - `"총 수익률은 {수익률}%입니다."` 문구로 수익률을 출력합니다.

- **수익률 계산 및 반올림 규칙을 명확히 정의했습니다**
    - 수익률은 `(총 상금 / 구입 금액) × 100`으로 계산합니다.
    - 소수점 둘째 자리에서 반올림하여 소수점 첫째 자리까지 출력합니다. (`%.1f%%` 형식)
    - 금액 단위 차이를 고려하여 수익률이 100%를 넘을 수 있습니다.

- **예외는 모두 IllegalArgumentException으로 통일합니다**
    - 검증 실패 시 `IllegalArgumentException`을 발생시키며, 메시지는 `ErrorMessage` 상수에서 관리합니다.
    - 이렇게 함으로써 예외 발생 위치는 달라도 메시지 형식을 일관되게 유지할 수 있습니다.
